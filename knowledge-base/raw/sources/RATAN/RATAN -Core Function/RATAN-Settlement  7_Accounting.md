### **Description **

- Ratan builds the capacity generating the payment accounting entry and feed to **Aspire **and **EBBS**, For **HK/JE/TH/TW**, the accounting entry would **EOD feeding** by **FileIT **between Ratan and Aspire, the accounting entry file format would be **csv**. For Other countries, the accounting entry would **real-time** feeding by **Solace **between Ratan and eBBS, the accounting entry message format would be **Json**.

### **Main Flow Diagram **

Add flow diagram and related description for user easy understanding

Conditions to trigger the accounting:
**New event: Cashflow status**: **Release/Settled/SWIFT_SUPPRESSED/FAILED**. send on real-time VD
**Withdraw event **:check if any accounting sent for before event, if so, send reversal entries (Reinstate action can trigger reverse accounting data generation).
**Specific for the swift suppressed cases : Instrument data is required for accounting also, but when cashflow is swift suppressed, the SSI stamping did not  happen yet, so when cashflow perform the accounting step, the SSI stamp would be triggered by accounting also**

| ****Send Sett Accounting**** | **Comments** |
| --- | --- |
| **RELEASED** | Send Accounting entry on real-time **VD** 1. If ‘RELEASED’ prior to VD ( e.g. VD-1, VD -2 etc) then hold the accounting generation first, only start to send the accounting entry from VD 6 am( local time which can be different by countries) in real time basics 2. If ‘RELEASED’ on VD then proceed the accounting generation & feeding in real time basics |
| **SETTLED** | Send depends on SENT flag (duplicate check) on real-time **VD** 1. If the accounting entry had been generated by the ‘RELEASED’ status on the same cashflow(Same id, event, business version) then bypass the accounting generation for ‘SETTLED’ status 2. If there’s no accounting entry generated before( e.g. the payment is SCB receipt & MT210 not required the cashflow, Ratan will skip the ‘RELEASED’ status directly moved to ‘SETTLED’), then Ratan would try to generate the accounting entry with ‘SETTLED’ status. The date & time Ratan try to generate the accounting entry will follow the same rule above with ‘RELEASED’ status |
| **SWIFT_SUPPRESSED** | Send on real-time **VD **(Un-suppress will be sent **reversal**) (need to stamp SSI; if no Nostro, no posting) 1. Agreed Ratan would generate the accounting entry for this status even there’s no swift message generated, it’s mainly for the case settlement happen out of Ratan e.g. directly debit the SCB account in other external settlement system 2. Given Ratan settlement ops didn’t intend to generate swift message for this cashflow, the Nostro static data is not mandatory for settlement process. For accounting generation purpose Ratan would do the additional Nostro query and there’s very low probability the Nostro is not available. The different case as below A. If Nostro is there, Ratan generate the accounting entry as normal B. **If Nostro is missing (i.e. new CCY), Ratan won’t generate the accounting entry,** but would capture the status & failure reason and make these visible for users. In H1 2024 we won’t build the capacity to fix this accounting generation failure in Ratan, user need to follow the BAU practice to fix this manually that’s in Oscar. |
| **FAILED** | Send real-time - Manually moved by settlement ops send on **VD** real-time, available in TLM on VD+1 - Auto Fail will be sent by **VD+1** 5AM SGT, available in TLM on VD+2 - On VD+1, when processing failed CF, reinstate action will trigger a reversal accounting entry. - When cashflow is released later, would send a new. |

**Exception Scenario for PSS support **

**Aspire**

| **Scenario** | **auto compensation** | **PSS action** |
| --- | --- | --- |
| File didn't generate at 10/10:30 PM local time | Job will auto run and try to regenerate file in following batch | Monitoring |
| File didn't generate until 11 PM local time | Job will auto run and try to regenerate file in following batch | Inform Dev for investigation/manually rerun failed job |
| File didn't generate until 12 PM local time | Job will auto run and try to regenerate file in following batch | Inform Aspire PSS to hold PSGL processing and provide ETA/manually rerun failed job |
| File didn't generate until 3 AM local time | NA | NA, as it would break Aspire-PSGL OLA timing, missing generated data will be included in next day's file File name and AsOfDate should be next day |

**eBBS:**

| **#** | **Scenario** | **Exception Handling** |
| --- | --- | --- |
| **1** | Ratan didn’t generate accounting posting, as missing mandatory field value | Accounting will be hold in RATAN as MISSING_INFO accounting status |
| **2** | Ratan hasn’t sent accounting posting, which is in HOLD accounting status | Ratan has scheduled job trying to send it, every 1 or 2 hours on VD |
| **3** | Ratan has sent accounting posting, EBBS has no feedback/feedback with exception codes TXN9999 and TEC0004 | Ratan will auto resend 3 times |
| **4** | User want to resend the accounting posting in RATAN if accounting posting in status **HOLD/SENT/REJECTED/MISSING_INFO** | User can manually resend accounting posting from GUI if necessary |
