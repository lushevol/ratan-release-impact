### Description:

1. **Settlement Message Flow** - **Murex **sends settlement cashflow messages to **Ratan** for processing. - Upon completion, **Ratan sends the updated cashflow status back to Murex**.
2. **SWIFT & Payment Message Conversion** - SWIFT messages and payment instructions are converted into **MX format** (ISO 20022) in **RATAN**.

### E2E Data Flow:

#### 1. **Settlement Message Flow (Cashflow Processing)**

cashflow data is sent from **Murex** to **Ratan** for processing, based on value date (VD) and processing flags:

- **Real-Time Flow (VD: T–1 to T+1)**: Payments with value dates from **T–1 to T+1** are delivered in **real-time** via **MQ** for immediate processing.
- **Batch Flow (VD: T+2 to T+7)**: Payments with value dates from **T+2 to T+7** are sent via **batch **files. → Generated by Murex and transferred to the **Ratan Shared NAS** via **SFTP** → *Excludes weekends and public holidays (e.g., December 25 and January 1)*
- **Fix Flag Cases**: Manual or corrective files are sent via **SFTP** to Ratan, regardless of value date, for reprocessing.

Upon successful processing, **Ratan sends the updated cashflow status back to MX 2.11** to ensure end-to-end reconciliation.
`Murex System
│
├──▶ Value Date: T–1 to T+1 → Sent in real-time → via MQ → Ratan (Immediate processing)
│
├──▶ Value Date: T+2 to T+7 → Batch file generated → Transferred via SFTP → Ratan Shared NAS
│ (Excludes weekends and public holidays: e.g., Dec 25, Jan 1)
│
└──▶ Fix Flag Cases (manual/corrective entries) → Sent via SFTP → Ratan (Reprocessing)
↓
Ratan processes the data
↓
Updated cashflow status sent back to MX 2.11`
#### 2. **SWIFT & Payment Message Conversion (to MX Format)**

SWIFT MT messages and Payment XML are sent from **Murex** to **Ratan** via **MQ** for conversion into **MX **(ISO 20022) format.

- This process is pending full decom migration from Murex, which will eventually centralize the logic.

This flow ensures standardized message formatting for downstream processing and reporting.
`Murex System
│
▼
SWIFT MT Messages & Payment XML
│
▼
Sent via MQ → Ratan
│
▼
Ratan converts messages into MX (ISO 20022) format
│
▼
Standardized output used for downstream processing
│
⚠️ Note: Full logic Decom is pending migration from Murex`

### Troubleshooting Steps:

- Murex will send batch file to RATAN every 2 hours. Batch files publishing from GMT 00:00 to 18:00. Each batch will contain 3 files as below naming convention: /apps/ratannas/murex_ratan_transfer/payment

o**FMRP_Murex_Payments_YYYYMMDD_XXX_Base.csv**

o**FMRP_Murex_Payments_YYYYMMDD_XXX_Snapshot.csv**

o**FMRP_Murex_Payments_YYYYMMDD_XXX_Completion_ZZZZ.csv**

- **YYYYMMDD** is the date of batch
- **XXX** is the sequence number within the day, 001,002,003…010
- **ZZZZ** is the count of payments in base file, used for recon purpose
- For the last file finished each day, an extra ending file will send to indicate the batch file finished for the day:** ****FMRP_Murex_Payments_YYYYMMDD_END.csv**

o If there is no batch file processed during the day, Murex will also send the ending file

- Since Murex cannot automatically re-generate the batch file, we need to hold the file transfer if there is any batch process issue. Murex need to wait the batch ACK from Ratan to process the next batch

oRatan will send ACK/NACK FILE to a different folder

- time out – 30 min: if Murex does not get any Ratan response in 30 minutes, the batch process will be on hold. Murex PSS will monitor this and check the root cause
- NACK: Ratan send the NACK response, Murex PSS check
- ACK/NACK file name
- **FMRP_Murex_Payments_YYYYMMDD_XXX_Ack.csv FMRP_Murex_Payments_YYYYMMDD_XXX_Nack.csv**
