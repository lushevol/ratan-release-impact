# Payment Integration

## The Status & Event matrix:

| | Owner | Event | Status | Comment |
| --- | --- | --- | --- | --- |
| 1 | STELLA | New Amend Withdrawal | PROJECTED: New cashflow created by Stella out of VD-5 window QUEUED: New cashflow created by Stella within VD-5 window CANCELLED: Cashflow cancelled by Stella | Stella can get the latest cashflow status from payment lake when handle these business events. |
| 2 | Cash Settlement Platform | Data Persistence | PROJECTED/QUEUED | Cash Settlement Platform would store the new inbond cashflows into payment lake. |
| 3 | Materialization | PROJECTED → QUEUED | Scheduled Job to materialize the cashflow falling into the V-5 window |
| 4 | NSTP process | QUEUED → PENDING→ VALIDATED | Post trade NSTP activities which Settlement Ops manually proceed the payments: - SSI Exception - NSTP review - CPN |
| 5 | Swift Generation | VALIDATED → RELEASED | Swift message generated and sent to routing application(FMSRE) |
| 6 | Settle in Swift Network | RELEASED → SETTELED | Swift message routed to Swift network for final settlement |
| 7 | Netting | PENDING → NETTING | Component cashflows after netting |
