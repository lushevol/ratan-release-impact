# Background

The trade affirmation/confirmation status is one of the key attributes to drive the cashflow STP/NSTP, Ratan would need to consume the trade confirmation status when the trade is affirmed/confirmed in TP systems.

# Function Flow

- Murex to TDS3: When there's new trade market event/trade status moving, Murex 2.11 would generate MxML message & send to TDS3. TDS3 would convert the MxML to SCBML & persist with logical model pattern.
- Stella to TDS3: Similarly any trade update from Stella( market event/trade status moving), there would be trade SCBML( defined by DM) sent to TDS3. TDS3 would persist the Stella trade with the logical model schema defined by DM team.
- TDS3 to Ratan: Ratan would consider TDS3 as the universal golden source for trade update and expect to get the generic trade SCBML which is following the logical model/physical model schema defined by DM.

- How to link the Murex 2.11 trade status with the underlying cashflows - Get the Source_System_Trade_Internal_Id from trade SCBML, e.g. the value is 'T1' - Use the value of Source_System_Trade_Internal_Id to lookup the field 'Trade_Id' from the cashflow data, to see if any cashflows with 'Trade_Id' as 'T1'
- Exception fix If the value of Source_System_Validation_Status is 'COMP' and there's cashflows tagged to the same trade 'T1', then lookup if there's exception '**Pending Confirmation/Affirmation' **under these cashflows. If there's exception then try to close this exception for this cashflow, if this is the only exception under this cashflow then move this cashflow to STP.
