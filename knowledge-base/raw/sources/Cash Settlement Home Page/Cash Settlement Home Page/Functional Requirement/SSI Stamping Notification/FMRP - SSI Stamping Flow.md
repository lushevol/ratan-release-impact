# SSI Exception Maker/Checker fixing actions

## Basic Principle

For Nostro/Vostro Vaule:

1. If missing/multi value for Nostro/Vostro, it will be blank value.
2. If it's same Maker/Checker with who submitted/rejected previously, Nostro/Vostro will be the same with Maker/Checker submit/reject page.
3. If it's different Maker/Checker with who submitted/rejected previously, Nostro/Vostro will be the same with initial page.

For Edit:

1. For Vostro related exception, 1. If there is, Vostro would be editable in default and no Edit button. 2. If there isn't, Vostro is not editable in default and doesn't have Edit button.
2. For Nostro related exception, 1. If there is, Nostro would be selectable in default and no Edit button. 2. If there isn't, Nostro is not selectable in default and has Edit button.
3. For Both related exception (Mismatch, adhoc), 1. Vostro is editable in default, Nostro is not selectable, but has Edit button.

# Effective Date

Ratan will be receiving the Effective date in the future where we will have the Start date and the End date of an SSI, Start Date / End Date will be updated only when there is an update (ie., existing SSI’s wont be updated with start date / end date for purpose of feeding to RATAN). Since RATAN stamping will be done on VD-5 so there should not be any scenario where Start Date / End Date is not available in ES layer.

- We would continue by adding new fields in Elastic search “Start_EffectiveDate, End_EffectiveDate, Core_EffectiveDate” and we will have a copy of the old SSI posted to ES with end date and with the Same SSI ID,

the New SSI would have a Suffix as _ED

on the Start date of the New SSI with suffix _ED the Old SSI would be deleted, (explained in the Excel below)

- When the new SSI is created, we will have a notification from DQSL to ES layer of the newly created SSI with an Effective Date on it
- On the Start Date there will not be another notification sent to Elastic search Layer.
