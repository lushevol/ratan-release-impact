# Background

In the settlement process rounding is required for both swift generation & accounting generation and there're different rounding approach for Ratan settlement process.

- Murex 2.11 booked cashflows: In the current BAU RATAN would take the rounded amount & send this amount to Razor. In H1 release Ratan would take the Murex original amount and apply the new agreed rounding rule.
- Stella booked cashflows: For strategy it's agreed Stella would do the rounding and send rounded amount to Ratan, but Stella didn't pick up this from backlog yet and won't be ready before the H1 2024 cashflow migration.

As agreed before Stella build the rounding logic Ratan need to implement the tactical solution do round the cashflows booked by Stella, as requested by PO Ratan would refer to Murex 2.11 BAU rounding logic to build the Ratan tactical rounding solution.

# Terminology of rounding

- **Rounding off **: 4 goes down & 5 goes up | Original Value | Precision | Round Off Value | | --- | --- | --- | | 5.11 | 1 Decimal | 5.1 | | 5.14 | 1 Decimal | 5.1 | | 5.15 | 1 Decimal | 5.2 | | 5.18 | 1 Decimal | 5.2 | | 5.6 | 1 Decimal | 5.6 | | 5 | 1 Decimal | 5 |
- **Rounding down (floor)**: always goes down Rounding down, sometimes referred to as "taking the floor" of a number means rounding down towards the nearest precision level. Means any decimals beyond the precision definition would be truncated. | Original Value | Round Up Value | Precision | | --- | --- | --- | | 5.001 | 5 | No Decimal | | 5.01 | 5 | No Decimal | | 5.1 | 5 | No Decimal | | 5.5 | 5 | No Decimal | | 5.6 | 5 | No Decimal | | 5.9 | 5 | No Decimal |

# Rounding Source & Destination

- Ratan would get original amount from Stella/Murex 2.11( from different file type as below).
- Ratan would perform the rounding on the original amount
- The rounded amount would be persisted on the logical model field Cashflow.Payment_Amount, this would be the only amount field available in the subsequent settlement process. User can only see this amount from GUI and only this amount be used by swift & accounting.

# Payment Rounding Table

How to use this table to round

- Get the Cashflow.Payment_Currency from cashflow data
- Use the Cashflow.Payment_Currency to query the precision & rounding type from below table
- Perform the rounding with precision & rounding type
- Remove the tailing zeros, e.g. if the precision is 2 decimal and original amount is 3.102, after the rounding calculation the rounded amount is **3.10**. Need to remove the trailing zero and the expected rounded amount is **3.1** .
- Persist the rounded amount on cashflow field Cashflow.Payment_Amount
