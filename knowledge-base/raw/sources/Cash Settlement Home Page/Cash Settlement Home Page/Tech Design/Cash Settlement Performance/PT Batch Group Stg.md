Overview

1，The maximum number of database connections is 25;

2，the maximum memory usage is 2GB.

3，Increased consumption time increases the likelihood of triggering Kafka's rebalance mechanism.

# 2，Bottleneck

1. Insufficient DB connection count;

only 4 of its dependent static-data services are configured, leading to SQL waiting under high concurrency.

2. Inappropriate code writing;

a. Both Materialize and Currency cutoff are single-parameter operations, resulting in twice the number of cashflow calls each time, leading to a large number of SQL queries.

b. Inappropriate use of the validate factory bean; under high concurrency, factory beans are frequently created instead of reused, resulting in object allocation overhead and CPU overhead.

# 3，Optimization direction

1, Increase the number of db connections

2, Code level

a) Materialize and Currency cutoff provide a batch SQL query interface to reduce SQL queries.

b) Make validatefactory singleton, initialize it only once.
