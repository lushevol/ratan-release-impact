# Cashflow Utilization Status Lifecycle

The FXU test case requests three additional cashflow statuses:

- `UTILIZED`
- `PARTIALLY-UTILIZED`
- `PASTDUE`

The source also uses `Ready` as the initial status for the four cashflows generated by the test trade.

## Known status vocabulary

The documented scenario contains the following values:

```text
Ready
UTILIZED
PARTIALLY-UTILIZED
PASTDUE
```

The source does not define canonical casing, separator conventions, display labels, or compatibility with existing cashflow status enumerations.

## Undefined lifecycle rules

The source does not specify:

- Valid transitions from `Ready` to utilization states.
- Whether `UTILIZED` and `PASTDUE` are terminal.
- Whether a cashflow can be both past due and partially utilized.
- Whether `PARTIALLY-UTILIZED` is determined by a positive `Remaining_Amount`.
- Which service owns status changes.
- Whether statuses are persisted, derived, or display-only.
- Whether status changes publish events or require downstream write-back.

These questions should be resolved before treating this vocabulary as a canonical lifecycle contract. Related event and write-back behavior must be checked against [[cashflow-status-change-event-contract]] and [[fx-cashflow-status-write-back]] rather than inferred from this test case.
