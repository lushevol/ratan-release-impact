# Cashflow Batch Control

Cashflow batch control is the first-level transaction control in [[ratan]]. It ensures that all cashflows generated by the same trade-level event are received as a complete set and that event batches for one trade are dispatched in order.

## Completeness gate

A batch is complete only when the number of received members equals its declared `Count`. Before that point, its cashflows must be held and must not be visible in the cashflow blotter or available to STP/NSTP processing.

For Stella, `Cashflow_Sequence` carries the packed value `BatchId_Sequence_Count`. For [[murex-211]], Ratan must derive equivalent values from cumulative `<Flows>` snapshots and retain a batch audit.

## Per-trade ordering

If batch 2 arrives before batch 1 for a trade, Ratan holds batch 2 even when it is complete. Once batch 1 is complete, Ratan dispatches batch 1 first. Batch 2 starts only after every batch-1 member has been sent to the STP/NSTP workflow.

The stated completion threshold is workflow dispatch, not final payment settlement. Later batches may therefore proceed before prior batches settle.

## Control gaps

The requirement does not define timeout, alerting, replay, duplicate-receipt treatment, manual override, or recovery for an indefinitely incomplete batch. The Murex inference algorithm is illustrative rather than formal.
