# Trade Event Undo Semantics

The UAT catalogue defines undo behavior according to the release state of the original cashflow, cancellation or termination payment, and termination fee.

## Intended State-Dependent Behavior

- If the original payment is not released, undoing a cancellation should revive the original cashflow.
- If the original payment is released but the cancellation is not released, the cancellation should be discarded and the original cashflow should remain released.
- If the cancellation message, identified as `MTx92`, is released, FO and MO should not be able to undo.
- For early termination, an unreleased fee should be cancelled when the relevant undo is performed.
- If the termination fee is released, MO should not be able to undo.
- Undo of expiry should discard cashflows generated by the undo.
- Future cashflows revived after undo should resume from the appropriate projected, released, or settled state rather than remaining suppressed.

## Observed Defect

The issue register reports that undo did not work for FT CPT termination test case 35. The issue concerned undo termination of test case 2, with trade `5068035670` and sample trade `4354505639`, and was marked as a high-priority Drop2 defect. The reported technical message was a minor-version mismatch.

This defect is evidence about a specific path and must not be generalized to all undo scenarios. The source does not provide formal regression or sign-off evidence.
