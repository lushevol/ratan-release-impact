# Deprecated Functional Requirements

Deprecated functional requirements are historical requirement records retained for context, traceability, or comparison with later specifications. Their presence does not make them authoritative for current product behavior.

The [[sources/25-cash-settlement-home-page--25-cash-settlement-home-page--22-functional-requirement--15-deprecated-docs--18-c--11740pp]] source is classified this way because its repository path places it under `Deprecated docs`. Its contents were not available during ingestion, so no specific superseded requirement or deprecation rationale is established.

## Handling guidance

- Preserve the original scope, terminology, and technical identifiers when extracting content.
- Distinguish historical behavior from current requirements.
- Compare against the current [[concepts/cashflow-blotter-functional-scope]] and the current Cashflow Blotter functional-requirement source.
- Keep CN-specific behavior separate from generic Cashflow Blotter behavior.
- Record a formal supersession link only when supported by document history or an authoritative replacement.
