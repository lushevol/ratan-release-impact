# Cashflow Blotter Functional Scope

The Cashflow Blotter functional-requirement outline identifies four areas that require specification: query criteria, layout, cashflow history audit, and cashflow actions. The source does not provide enough detail to establish authoritative behavior.

## Query Criteria

The complete specification should identify:

- Searchable fields and supported operators
- Required, optional, and default criteria
- Validation and error behavior
- Result ordering, pagination, and maximum result size
- Whether the query returns current materialized cashflows, historical records, or both
- The relationship between query scope and [[cashflow-materialization]]

## Layout

The complete specification should define:

- Required columns and their authoritative field definitions
- Sorting, grouping, filtering, and pagination behavior
- Status and version presentation
- Visibility rules by user role or operational context
- How amended, superseded, withdrawn, duplicate, and netted records are displayed

No layout details are supplied by the source.

## Cashflow History Audit

The complete specification should clarify:

- Whether history is represented as events, versions, or both
- How the current record is distinguished from historical records
- How amendments and supersession are linked
- Whether withdrawn and duplicate records remain visible
- Audit retention, access, and display requirements

The heading may relate to [[cashflow-lifecycle-supersession-and-audit-history]] and [[cashflow-amendment-supersession]], but it does not confirm that either model is implemented by the blotter.

## Cashflow Actions

The complete specification should define:

- Supported user or system actions
- Preconditions for each action
- Permissions, approvals, and confirmations
- Resulting [[cashflow-status-lifecycle]] transitions
- Error and retry behavior
- Audit events generated by each action
- Whether actions are atomic per cashflow or can operate across trades, groups, or bulk selections

Rules from [[bulk-manual-stp-group-blotter]] must not be transferred to the Cashflow Blotter without explicit evidence.

## Open Specification Gaps

The source does not resolve the authoritative query contract, data contract, history model, action inventory, permission model, or lifecycle integration. A detailed UI design, API specification, data model, or test matrix is needed before implementation behavior can be confirmed.
