# Ratan Cashflow ID Generation Logic

This functional requirement defines how [[ratan]] normalizes imported cashflow IDs and generates IDs for netting and split results. All Ratan cashflow IDs are intended to be 12 characters. The document also requires uniqueness across Ratan services and processes and calls for concurrency handling during generated-ID allocation.

## Imported cashflow ID normalization

| TP System | Cashflow id length from TP system | Ratan cashflow id processing logic | Comment |
| --- | --- | --- | --- |
| Stella | 12 | - Keep the id consumed from STELLA, which is a length 12 | Stella cashflow id: 002023042196, Ratan cashflow id: 002023042196 |
| Murex 2.11 | maximum10 | - Padding ‘M’ as prefix to indicate it is a Murex cashflow - Padding '0' between 'M' and Murex flow id to ensure id length is 12 | Murex flow id: 1234567, Ratan cashflow id: M00001234567 Murex flow id: 1234567890, Ratan cashflow id: M01234567890 |
| MxCash | maximum10 | - Padding ‘R’ as prefix to indicate it is a Razor cashflow - Padding '0' between 'R' and Razor flow id to ensure id length is 12 | Razor flow id: 1234567, Ratan cashflow id: R00001234567 Razor flow id: 1234567890, Ratan cashflow id: R01234567890 |
| | | | |

The preservation rule is specifically stated for [[stella]]. The `M` prefix applies to [[murex-2-11]], while the `R` prefix applies to [[mxcash]]-derived Razor cashflows. The document does not specify validation or error handling for blank, non-numeric, already-prefixed, or overlength upstream IDs.

## SWIFT Field 20 generation

- The maxim length of swift field 20 is 16.
- For BCS the field 20 name conversion it's 'EQ02003791883175' - EQ is the hardcode prefix which stands for Equity - '02' is the branch code of booking entity - 00379188317 is the cashflow id generated by FMRP Stella, with maxim length as 12.
- Field 20 can be combination of alphabet and numeric.

This is a [[bcs]]-specific example, not a stated universal Field 20 format. The provided value and described components total 15 characters, although the stated maximum is 16 and the embedded FMRP Stella ID is described as having a maximum length of 12. This ambiguity is tracked in [[what-is-the-authoritative-bcs-swift-field-20-format]].

## Generated IDs for Ratan-created cashflows

- Need to populate new cashflow id for netting/split cashflow
- Cashflow id must be unique across Ratan services/process
- Netting resultant cashflow id name conversion is 'N' + 11 numeric value - 'N' stands for 'Netting' - 11 length numeric id starting from 00000000001 - 11 length numeric id is auto increased
- Split cashflow id name conversion is 'S' + 11 numeric value - 'S' stands for 'Split' - 11 length numeric id starting from 00000000001 - 11 length numeric id is auto increased

Accordingly, netting results use `N00000000001` as the stated starting format and split results use `S00000000001`. The source establishes the format and cross-process uniqueness requirement but does not define an allocator, storage model, reset policy, or retry behavior. See [[ratan-cashflow-id-management]] and [[concurrency-safe-id-allocation]].

## Generation API

```js
{ Request_Service: "Manual netting"/"Auto Netting"/"Manual Split"/"Auto Split" CashflowId_Type: "Netting" or "Split" }
```

- If the CashflowId_Type is 'Netting' then the cashflow prefix is 'N', otherwise is 'S'
- Concurrency should be considered if multi process requesting the cashflow id generation

The supplied request form is conceptual rather than implementation-ready JSON. It does not specify validation of `CashflowId_Type`, the effect of `Request_Service`, or permitted service/type combinations. The requirement for globally unique values under concurrent requests is tracked in [[how-is-ratan-cashflow-id-uniqueness-enforced]].
